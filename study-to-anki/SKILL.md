# Study to Anki：学习素材 → Markdown → Anki 闪卡

将任何学习主题或学习材料转化为结构化的学习内容，经用户审阅确认后，生成可直接导入 Anki 的 .apkg 闪卡文件。

## 核心流程

```
需求梳理 → 素材收集整理 → 生成结构化 Markdown → 用户审阅确认 → 生成 .apkg 文件 →（可选）归档到 GitHub
```

每一步都需要用户确认后才能进入下一步。不要跳过审阅环节。

---

## 第零步：需求梳理（使用 brainstorming）

在开始生成内容之前，需要和用户充分沟通，明确学习目标、范围和偏好。

### 检查 brainstorming skill

检查当前环境是否已安装 `superpowers:brainstorming` skill：

- **如果已安装**：调用 `Skill` 工具加载 `superpowers:brainstorming`，按照它的流程和用户一步步确认需求细节（一次问一个问题，涵盖主题、范围、风格等）。brainstorming 完成后再继续后续步骤。
- **如果未安装**：告诉用户有一个专门的 brainstorming skill 可以帮助更系统地梳理需求，询问是否要安装。如果用户不想安装，则由本 Skill 直接用以下方式逐一确认。

### 需要确认的信息

通过 brainstorming 或直接沟通，明确以下内容：

1. **学习主题**（如"血常规报告"、"计算机网络协议"、"法律条文"）
2. **是否有提供学习材料**：
   - 无材料 → 从零生成（基于知识储备）
   - 有材料 → 收集并整理材料内容（见第一步）
3. **覆盖范围**（精简入门 / 常见核心 / 全面覆盖）
4. **闪卡结构**：
   - 单条目大卡片（一卡包含所有信息）
   - 拆分小卡片（每个知识点一张卡）
5. **语言风格**（通俗易懂 / 半专业 / 专业深入）

确认后规划出：
- 需要生成哪些分类文件（按子领域分文件，便于分段审阅）
- 每个条目包含哪些字段（如"含义"、"正常范围"、"高/低影响"等）
- 大约覆盖多少条目

向用户展示规划方案，获得确认后再开始。

---

## 第一步：收集和整理学习材料

根据用户是否提供了学习材料，走不同的路径：

### 路径A：用户提供了学习材料

用户可能提供以下类型的材料：

**PDF 文件**：
- 使用 `Read` 工具读取 PDF 内容（大文件需要指定 pages 参数分段读取）
- 提取关键知识点，按规划的字段结构整理

**网页链接**：
- 使用 `mcp__web_reader__webReader` 工具（如果可用）抓取网页内容
- 或使用 `WebFetch` / `WebSearch` 工具获取信息
- 从网页中提取与学习主题相关的内容

**本地文档**（txt、md、docx 等）：
- 使用 `Read` 工具直接读取文本文件
- docx 等格式如有对应 MCP 工具可使用，否则提示用户提供文本版本

**混合材料**：
- 如果用户提供了多种材料，逐一读取，然后交叉比对整合
- 注意标注信息来源，避免矛盾

**材料整理原则**：
- 从材料中提取核心知识点，而非照搬原文
- 按照规划的字段结构重新组织内容
- 如果材料内容不够全面，用自己的知识补充，但需告知用户哪些是补充的
- 如果材料之间有冲突，以更权威的来源为准，并在内容中标注

### 路径B：从零生成

用户没有提供材料，直接基于知识储备生成内容。进入第二步。

---

## 第二步：生成 Markdown 学习内容

### 文件结构

在用户的工作目录下创建：

```
<项目目录>/
├── content/           # Markdown 学习材料
│   ├── 分类1.md
│   ├── 分类2.md
│   └── ...
└── output/            # Anki 输出
```

### Markdown 格式规范

每个文件必须严格遵循以下格式，因为脚本依赖此结构解析：

```markdown
# 分类名称（英文/中文说明）

分类的简要介绍。

---

## 1. 条目名称 (英文缩写)

**字段1**：内容...

**字段2**：内容...

**字段3**：内容...
```

关键规则：
- 文件顶部用 `#` 标题写分类名
- 每个条目用 `##` 标题，编号 + 名称
- 字段用 `**字段名**：` 格式（粗体 + 中文冒号）
- 条目之间用 `---` 分隔
- 字段内容支持多行，用空行 + 下一个 `**字段**` 分隔

### 生成原则

- 语言风格按用户选择（默认通俗易懂）
- 每个字段内容具体、实用，避免空泛描述
- 类比和比喻有助于理解（如"白细胞是身体的保安"）
- 正常范围或标准值要注明单位
- 如果涉及数值，标注关键阈值（如"低于 XX 需要紧急处理"）

### 并行生成

各分类文件内容独立，可以并行生成以提高效率。所有文件生成后，一次性展示给用户审阅。

---

## 第三步：用户审阅

**不要跳过这一步。** 展示文件列表和每个文件包含的条目数量，明确请用户确认：

- 内容是否正确、准确
- 是否需要补充或删除某些条目
- 语言风格是否满意
- 字段结构是否合适

等待用户明确说"确认"或"可以"后，再进入下一步。如果用户提出修改，先修改 Markdown 文件，再次确认。

---

## 第四步：生成 Anki .apkg 文件

### 环境检查

```bash
python3 -c "import genanki" 2>/dev/null || pip3 install --user genanki
```

如果安装失败，尝试 `pip3 install --break-system-packages genanki`。

### 运行转换脚本

本 Skill 自带通用转换脚本 `scripts/generate_apkg.py`，用法：

```bash
python3 <skill-path>/scripts/generate_apkg.py \
  <content_dir> \
  <output_file> \
  "<deck_name>" \
  "正面字段名" "背面字段1" "背面字段2" ...
```

第一个字段名会作为卡片正面显示的内容。

**示例**（血液检查）：

```bash
python3 /path/to/study-to-anki/scripts/generate_apkg.py \
  ./content \
  ./output/血液检查学习卡片.apkg \
  "血液检查学习卡片" \
  "名称" "所属分类" "是什么" "正常范围" "偏高意味着" "偏低意味着"
```

注意：脚本中的字段名必须和 Markdown 中 `**字段名**：` 完全一致（不含粗体标记）。

### 验证

运行后检查：
1. 脚本输出显示正确的条目数量
2. 输出文件大小合理（通常 50KB~500KB）
3. 向用户报告文件位置和卡片数量

---

## 第五步：归档到 GitHub（可选）

.apkg 生成并验证后，**主动询问用户**是否要把这次制作的牌组归档到 GitHub 仓库。只有用户明确同意才执行；用户拒绝或跳过则流程结束。

建议提示语：「牌组已生成。是否要归档到 GitHub 仓库 `pipony/myAnkiDecks`？」

### 归档仓库

- 仓库地址：`git@github.com:pipony/myAnkiDecks.git`（SSH）
- 用途：个人（AI）制作的 Anki 牌组归档。仓库根目录的 `README.md` 维护一张牌组清单表格，每归档一个牌组就往表格里追加一行。

### 归档流程

1. **克隆仓库到临时目录**：

   ```bash
   git clone git@github.com:pipony/myAnkiDecks.git /tmp/myAnkiDecks
   ```

2. **为本牌组建目录**：在仓库根目录下新建一个以主题命名的目录（如 `汽车车标学习/`），把本次生成的 `.apkg` 复制进去。目录名用能概括主题的中文名，不要用日期或随机串。

3. **更新 README.md（关键）**：归档时**先读取仓库里已有的 `README.md`**，找到「## 牌组列表」下的表格，在表格末尾**追加一行描述本次归档的牌组**。四列内容：

   - **目录**：本次新建的目录名
   - **牌组**：`.apkg` 文件名
   - **说明**：一句话简介（覆盖范围、分类、卡片张数等）
   - **制作方式**：**如实**写明这个牌组是怎么做出来的——
     - 素材/图片**来源**：来自某个公开数据集/网站/用户提供的材料，还是 AI 从零生成？有外部来源就写明出处（带上链接）
     - 内容（字段）**谁生成**：通常是「AI 生成 + 用户审阅确认」
     - 用什么**打包**：通常是 Python（genanki）
     - **必须按本牌组的真实制作过程写，不要套用别的牌组的描述，不要编造来源。**

   不要改动其它已有行。如果仓库还没有 `README.md`（首次归档），按下面的模板新建一个：

   ```markdown
   # myAnkiDecks

   个人（AI）制作的anki牌组归档。

   ## 牌组列表

   | 目录 | 牌组 | 说明 | 制作方式 |
   |------|------|------|----------|
   | <主题目录> | <文件>.apkg | <简介> | <制作方式> |

   ## 使用方法

   1. 下载对应的 `.apkg` 文件。
   2. 在 Anki 桌面版中选择「文件 → 导入」，或直接双击 `.apkg` 文件。
   3. 牌组将出现在 Anki 中，可直接开始学习。
   ```

4. **提交并推送**：

   ```bash
   cd /tmp/myAnkiDecks
   git config user.name "pipony"
   git config user.email "pipony@users.noreply.github.com"
   git add -A
   git commit -m "Add <牌组名> Anki deck"
   git push
   ```

   仓库默认分支为 `main`。若克隆后是空仓库，先 `git branch -M main` 再 `git push -u origin main`。

5. **清理与反馈**：删除临时克隆 `rm -rf /tmp/myAnkiDecks`，向用户报告仓库地址 `https://github.com/pipony/myAnkiDecks` 以及本次新增的目录/文件。本地原始 `.apkg` 和工作目录不删改，归档只是把副本放进 git 仓库。

---

## 注意事项

- 生成内容后一定要等用户确认，不要自作主张直接做 Anki
- 如果用户提供了材料，优先基于材料内容生成，不足部分再补充
- 如果用户的 Markdown 文件格式和模板不同（如字段名不同），在运行脚本时传入对应的字段名即可
- 脚本支持 `##` 和 `###` 两种标题级别，自动选择条目最多的一种
- 每张卡的正面显示第一个字段，背面显示其余所有字段
- 脚本为纯 Python，依赖 `genanki` 库，无需 Anki 客户端
